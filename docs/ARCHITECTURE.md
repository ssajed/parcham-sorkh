# معماری فنی پرچم سرخ

## الگوی معماری

پرچم سرخ با معماری **Modular Monolith** روی Laravel ساخته می‌شود. برنامه یک استقرار و یک پایگاه داده دارد، اما کد دامنه بر اساس مسئولیت‌های کسب‌وکار در ماژول‌های مستقل سازمان‌دهی می‌شود. ساخت سرویس‌های جداگانه، ارتباط شبکه‌ای بین ماژول‌ها یا ایجاد لایه‌های انتزاعی بدون نیاز واقعی، جزو تصمیم فعلی پروژه نیست.

## مرزبندی فعلی ماژول‌ها

| ماژول | مسئولیت |
| --- | --- |
| Auth | ثبت‌نام، ورود و درخواست‌های تغییر دسترسی همراه‌جو/همراه‌یار |
| Accounts | پروفایل و اطلاعات حساب |
| Admin | داشبورد، کاربران، بررسی حساب‌ها و دسترسی مدیران |
| Accompaniment | درخواست‌های همراهی و قواعد مربوط به آن |

کدهای مشترک و زیرساختی در جایگاه‌های استاندارد برنامه قرار می‌گیرند:

- app/Models: مدل‌های هسته‌ای مشترک مانند User
- app/Http: کنترلر پایه و middlewareهای سراسری
- app/Rules: قواعد اعتبارسنجی مشترک
- app/Support: ابزارهای مستقل از رابط کاربری مانند تبدیل تاریخ شمسی
- routes/web.php: نقطه اتصال مسیرهای HTTP به ماژول‌ها

## قواعد توسعه ماژول‌ها

1. کنترلر و درخواست اعتبارسنجی مختص یک قابلیت در ماژول مالک همان قابلیت قرار می‌گیرد.
2. ماژول‌ها نباید به View یا Controller ماژول دیگر وابسته شوند؛ اشتراک‌گذاری از طریق مدل یا کلاس‌های دامنه‌ای روشن انجام می‌شود.
3. middlewareهای احراز هویت و مجوز عمومی در app/Http/Middleware باقی می‌مانند.
4. از ساخت ServiceProvider، Interface، Repository یا پوشه خالی بدون مصرف واقعی خودداری می‌شود.
5. منطق مجوز باید در سمت سرور اعمال شود؛ مخفی‌کردن لینک یا دکمه جایگزین کنترل دسترسی نیست.
6. عملیات حساس چندمرحله‌ای باید در تراکنش پایگاه داده انجام شود و برای منابع مشترک، قفل مناسب داشته باشد.
7. تغییر schema فقط با Migration جدید و پس از توضیح اثر آن انجام می‌شود؛ Migrationهای اجراشده بازنویسی نمی‌شوند.

## هویت و مجوزها

- نقش اصلی مدیر در users.role = admin نگهداری می‌شود و حساب مدیر باید وضعیت تأییدشده داشته باشد.
- دسترسی همراه‌جو و همراه‌یار مستقل از نقش اصلی و در ستون‌های can_be_companion_seeker و can_be_companion_helper نگهداری می‌شود.
- ورود به پنل مدیریت علاوه بر احراز هویت، به middleware سمت سرور admin وابسته است.
- اعطای دسترسی مدیر فقط به حساب تأییدشده انجام می‌شود.
- مدیر جاری نمی‌تواند دسترسی خودش را از پنل لغو کند و آخرین مدیر فعال قابل تنزل نیست.

## رابط کاربری و زمان

- زبان رابط کاربری فارسی و جهت آن RTL است.
- تاریخ قابل مشاهده برای کاربر با ابزار App\Support\JalaliDate نمایش داده می‌شود.
- ورودی تاریخ شمسی در لایه رابط کاربری به مقدار میلادی استاندارد تبدیل می‌شود؛ ذخیره‌سازی و منطق دامنه بر مبنای تاریخ استاندارد باقی می‌ماند.
- ساعت‌های قابل مشاهده باید با قالب فارسی نمایش داده شوند؛ مقدار ذخیره‌شده زمان ۲۴ ساعته استاندارد است.

## کیفیت و تست

- تست‌های PHP در tests/Feature و tests/Unit نگهداری می‌شوند.
- CI روی PHP 8.5، SQLite in-memory و Node.js 22 تست‌ها و build فرانت‌اند را اجرا می‌کند.
- تغییرات مربوط به دسترسی باید حداقل حالت مجاز، غیرمجاز، حساب تأییدنشده و حفاظت از آخرین مدیر فعال را پوشش دهند.
- قبل از ادغام هر تغییر، git diff --check، تست‌های Laravel و npm run build اجرا شوند.

## محدوده‌های خارج از این فاز

این مستند به معنی تکمیل چرخه پیشنهاد همراه‌یار، توافق، رزرو ظرفیت، اجرای همراهی، پیامک واقعی یا انقضای خودکار درخواست‌ها نیست. هرکدام از این قابلیت‌ها فاز مستقل خود را دارند.
